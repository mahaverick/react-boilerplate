# react-boilerplate — Modernization Design

Date: 2026-09-14
Status: Approved (design); implementation plan pending
Companion spec: `express-boilerplate/docs/superpowers/specs/2026-09-14-modernization-design.md`

## 1. Problem

`react-boilerplate` was last touched on 2024-12-23 (10 commits). Like its
backend counterpart it is a stack generation behind every production frontend
in the production fleet:

| | react-boilerplate (today) | the two reference dashboards (today) |
|---|---|---|
| React | 18.3 | 19 + React Compiler |
| Routing | react-router-dom 7, hand-written route objects | TanStack Router, file-based, generated tree |
| Server state | @tanstack/react-query **and** Redux Toolkit | TanStack Query only |
| Client state | Redux Toolkit (3 slices) | Zustand + Immer (17 stores) |
| Forms | react-hook-form + @hookform/resolvers | TanStack Form + Zod 4 |
| UI primitives | Radix (7 packages), 12 components | Base UI + shadcn CLI, 59 components |
| Styling | Tailwind 3 + postcss + autoprefixer | Tailwind 4 via `@tailwindcss/vite` |
| Build | Vite 6 | Vite 8 |
| Tests | 1 test file | Vitest + jsdom, colocated, ~100 test files |
| Observability | none | OpenTelemetry web + PostHog |
| Crypto | crypto-js | removed |

Shipping both Redux and React Query is the clearest symptom: the boilerplate
records a migration that was still in progress two years ago.

### 1.1 Measured before-state

Recorded on 2026-09-14, Node v24.17.0, `npm install`:

| Step | Result |
|---|---|
| `npm install` | passes |
| `npm run build` | passes |
| `npm test` | passes — 1 test file, 1 trivial test |

The frontend is green, but green over almost nothing: `src/tests/example.test.ts`
is the whole suite. Across both boilerplates there are **two passing tests**,
and one of the two backend suites cannot even be imported. That is the gap
section 7 exists to close, and it is why coverage thresholds are a gate here
rather than a report.

## 2. Decisions

Settled before this document: derive from the reference dashboard and strip; full parity minus
domain (so billing, onboarding and team-management screens ship); infrastructure
wired and required; latest everything including majors; GitHub template +
`pnpm bootstrap`.

the reference dashboard is the source of truth over the second reference dashboard — it is the richer of the two
(TanStack Form, `_onboarding` route group, markdown, motion, Turnstile) and
the second reference dashboard is effectively a subset.

## 4. What ships

Source paths are in `the reference dashboard`.

### 4.1 Routing — `src/pages` -> `src/routeTree.gen.ts`
File-based, `autoCodeSplitting: true`, generated by `pnpm generate-routes`
(`tsr.config.json`). Route groups mirror the reference dashboard:

- `__root.tsx`
- `_auth.tsx` + `_auth/{login,register,forgot-password,reset-password,verify-email,magic-link/verify}.tsx`
- `_onboarding.tsx` + `_onboarding/onboarding/{workspace,plan,payment-return}.tsx`
- `_protected.tsx` + `_protected/{dashboard,profile,settings,team,billing,$}.tsx`
  and `_protected/settings/{general,members,billing,security}.tsx`
- `invitations/accept.tsx` — public route, ported from the reference dashboard with its test.
  The landing page for the backend's `POST /api/v1/invitations/:token/accept`.
- `oauth/callback.tsx` — **new code**: the public route the backend's Google
  OAuth callback redirects to, which exchanges the handoff for a session.
  the reference dashboard has no equivalent — its `_protected/oauth/consent.tsx` is the other
  side (the reference backend acting as an OAuth *provider*) and is not ported.

`_protected/team` and `_protected/settings/{general,members,security}` are
**new pages, not ports**: the reference dashboard's settings tree is
`{acquisition,badges,billing}`, which is domain-specific.

`src/pages/external-entry-routes.ts` ships with its comment intact: it is the
registry that stops someone deleting a route with no in-repo references
(Stripe/email/DB-stored entry points). The `routeTree.gen.ts` never-hand-edit
rule goes into `CLAUDE.md`.

Dropped: every `_protected/analyze/*`, `metrics/*`, `acquisition*`, `insights`,
`assistant`, `reports`, `attribution`, `conversion`, `admin/tenants/*` route.

### 4.2 HTTP layer — `src/http`
Port `client.http.ts`, `interceptors.http.ts`, `auth-refresh.http.ts` and
`sse.http.ts` with their tests. This is the single highest-value piece in the
repo: the refresh-race handling (one in-flight refresh, queued retries) and the
`X-Tenant-ID` scope-header injection are exactly what a new project gets wrong.

Keep `VITE_API_BASE_URL=""` meaning same-origin, and keep the `??` (not `||`)
that makes empty-string distinct from unset — with the comment explaining why.

### 4.3 Server state — `src/queries`
Port the generic query modules only: `auth`, `profile`, `onboarding`,
`billing`, `tenant`, `tenant-settings`, `team`, `scope`, `header-scoped`
(the pattern for invalidating on workspace switch), plus
`scope-switch-auth-cache`. Query client with the sync-storage persister and
devtools. Dropped: 24 domain query modules.

### 4.4 Client state — `src/states`
Port `auth.state`, `breadcrumb.state`, `tenant.state`, `global.state`,
`store.state` (generalized to a workspace/scope selector). Zustand + Immer +
persist. Dropped: acquisition-columns, conversion-filters, chat, metric,
date-range (moves to a recipe).

### 4.5 UI kit — `src/components/ui`
Port 48 of the reference dashboard's 50 components (the other 9 files in that directory are
colocated tests): alert, alert-dialog, avatar, badge, breadcrumb,
button, calendar, card, checkbox, collapsible, combobox, data-table, date-picker,
dialog, dropdown-menu, empty, field, hover-card, image, input, input-group,
item, label, numeric, option-list, popover, progress, radio-group, scroll-area,
segment-tabs, select, separator, sheet, sidebar, skeleton, slider, sonner, spinner,
status-chip, stepper, suspense-boundary, switch, table, tabs, textarea, toggle,
toggle-group, tooltip — with their colocated tests. `components.json` ships so
`pnpm dlx shadcn add` keeps working.

Dropped: chart, filter-picker, and any component whose props encode a metric or
grade.

### 4.6 Hooks, utils, constants
Hooks: `use-debounce`, `use-mobile`, `use-pagination`, `use-theme-switcher`,
`use-system-theme-detector`, `use-local-storage-boolean`, `use-expanded-keys`,
`use-in-view`, `use-on-window-resize`, `use-route-breadcrumbs`,
`use-current-tenant-role`, `use-format-preferences`, `use-posthog-flag`.

Utils: `error`, `form`, `global`, `csv`, `navigation`, `display-name`,
`concurrency`, `oauth`, `format-config`. Dropped: every `*metric*`,
`*acquisition*`, `*profitability*`, `*campaign*`, `*creative*`, `*connector*`.

Constants: `environment`, `format`, `navigation`, `settings`, `tabs`, `otel`,
`posthog`, `feature-flags`, `empty-states`, `legal`, `support`, `countries`.

### 4.7 Observability — `src/observability`
Port `tracing.ts` (OTel web: document-load, fetch, xhr, long-task,
user-interaction), `posthog.ts`, `url-redaction.ts` and `context-analytics.ts`
generalized to tenant/user context only. `url-redaction` ships with its tests —
it is the piece that stops tokens and ids leaking into span names.

### 4.8 Design system
`src/styles/global.styles.css` carries the shadcn semantic tokens
(`--background`, `--foreground`, `--primary`, `--muted`, `--destructive`,
`--border`, `--ring`, `--chart-1..5`, `--sidebar-*`, `--success`, `--warning`),
light and dark. `STYLESEED.md` ships as the token contract; the
"consume only these tokens, never named Tailwind colors" rule moves into
`CLAUDE.md` and is enforced by an eslint `no-restricted-syntax` rule on
`bg-red-*`-style literals.

`PRODUCT.md` does **not** ship — it is the reference product's brand and register. A
stub `PRODUCT.md` explaining what belongs there ships instead.

### 4.9 Errors and boundaries
`src/components/errors/{error-boundary,not-found}.tsx`, the route-level
`errorComponent` pattern, and `suspense-boundary.tsx`.

## 5. New code — not ported

### 5.1 Env validation — `src/configs/env.config.ts`
A Zod 4 schema over `import.meta.env`, parsed once at module load, exported
typed. Fails the dev server and the build with a readable list on a missing
`VITE_*`. `.env.example` is generated from it. Neither the reference dashboard nor the second reference dashboard has this.

### 5.2 Generated API types
The backend emits `openapi.json` (backend spec 5.2). A `pnpm generate-api-types`
script turns it into `src/types/api.gen.ts`, so the axios layer is typed from
the server contract instead of hand-written duplicates. This is the one piece
that makes the two boilerplates a matched pair rather than two repos.

The two repos are independent GitHub templates, so the file crosses over HTTP,
never over the filesystem: `pnpm generate-api-types --from
http://localhost:4040/openapi.json`, defaulting to `VITE_API_BASE_URL`.
`api.gen.ts` is committed, so this repo builds, tests and deploys standalone
with no backend running; CI regenerates and fails on drift only when
`BACKEND_OPENAPI_URL` is set.

### 5.3 `scripts/bootstrap.ts`
Prompt for project name -> rewrite `package.json`, `index.html`, docs, repo
URLs -> write `.env` from the env schema -> `pnpm generate-routes` -> print the
dev URL and the backend it expects.

### 5.4 `vitest.setup.ts`
Ported verbatim including its long comment — the Node >=22 experimental
`localStorage` shim is non-obvious and its absence breaks every zustand
persist test.

## 6. Conventions

`eslint-plugin-check-file` pins `*.page.tsx` / `*.state.ts` / `*.queries.ts` /
`*.utils.ts` / `*.constants.ts` / `*.http.ts` naming and kebab-case folders.

**No manual memoization.** React Compiler is on; `useMemo`/`useCallback`/
`React.memo` are noise. This goes in `CLAUDE.md` and is enforced by lint.

**No standalone typecheck script** — `pnpm build` (`tsc -b`) is the type gate,
matching the reference dashboard.

## 7. Testing

Vitest 5 + jsdom 30, tests colocated next to source (the reference dashboard's convention, not
a `tests/` tree).

### 7.1 Two departures from the reference dashboard, both deliberate

the reference dashboard has **no** `@testing-library/react` in its dependencies. Its component
and hook tests import `createRoot` from `react-dom/client` directly — 382
occurrences, with no shared render helper — and hand-roll mounting, act
wrapping and cleanup in every file. The boilerplate does not port that. It adds
`@testing-library/react` 16.3.3, `@testing-library/user-event` 14.6.7 and
`@testing-library/jest-dom` 7.0.1, and tests behaviour through the DOM the way
a user reaches it.

Five the reference dashboard test files assert against **source text** — reading the component
file with `fs.readFileSync` and running regexes over it. `card.test.tsx`
matches Tailwind class names out of `card.tsx` to check spacing. That is a test
of a string, not of a component: it passes when the class is present and the
component is broken, and fails on a harmless refactor. Not ported.

The pattern is kept in exactly one place, where it is legitimate:
`global.styles.test.ts` asserting on the CSS token file. Design tokens have no
runtime surface to assert against, so a contract test over the stylesheet text
is the only way to pin them — and it is a genuine contract, not a proxy for
behaviour.

### 7.2 Coverage

the reference dashboard has no coverage configuration at all. The boilerplate ships the v8
provider with the same 80% thresholds as the backend (lines, functions,
branches, statements) and CI runs `vitest run --coverage`, so they gate.

### 7.3 What gets tested

The http layer (client, interceptors, refresh race, SSE), every state store,
every hook, the auth/onboarding/team/billing route guards, and each UI
component with behaviour beyond rendering its children.

## 9. Risks

1. **TypeScript 7** — same risk as the backend; the two repos must resolve it
   the same way. Verify `typescript-eslint` 8.70 and `tsc -b` project references
   under TS 7 before porting anything.
2. **@tanstack/react-table 8 -> 9** is a major on a library the reference dashboard uses
   heavily in `data-table.tsx`. Port `data-table` early and against v9's API,
   rather than copying the v8 version and migrating later.
3. **Vitest 5 + jsdom 30** together change the test environment twice. The
   `localStorage` shim in `vitest.setup.ts` is written against a specific Node
   behaviour and must be re-verified, not assumed.
4. **Base UI 1.8** vs the reference dashboard's 1.6 — component APIs may have shifted; the
   45-component port is where that surfaces.
5. **Scrub completeness** — same grep gate as the backend, plus a check that no
   `--chart-*` token consumer or metric-shaped prop survives.

## 10. Sequencing

The backend contract (backend spec section 11) is specified first; this repo's
`src/queries` and `api.gen.ts` depend on it. Within this repo the order is:
toolchain and config -> env validation -> http layer -> states -> UI kit ->
route groups -> pages -> observability -> docs and hygiene. Each stage leaves
`pnpm build` and `pnpm test` green.


## 11. Standards

### 11.1 Documentation — JSDoc

the reference dashboard carries JSDoc in 426 of 586 source files (73%). As on the backend, the
convention exists and the enforcement does not — `eslint-plugin-jsdoc` is used
in no repo in the fleet. It ships here at 64.4.0 with the same configuration as
the backend spec section 12.1: `require-jsdoc` with `publicOnly: true`,
descriptions required, **types not required** (TypeScript already carries them),
and a file-header comment on every module explaining what it is for and, where
not obvious, why it exists.

Components additionally document their props interface and carry an `@example`
showing the common usage — this is what makes the UI kit usable without reading
its internals.

### 11.2 Accessibility

`eslint-plugin-jsx-a11y` 6.10.2, which appears in no repo in the fleet today.
Base UI's primitives are accessible by construction, but the application code
composing them is where labels, roles and focus management get dropped. Axe
assertions on the UI kit's interaction tests.

### 11.3 Supply chain and secrets

`pnpm audit --prod` in CI, `dependabot.yml`, gitleaks at both the pre-commit
and CI layers, `.gitleaks.toml` and `SECURITY.md` — matching the backend.

One frontend-specific gate: **no secret-shaped `VITE_*` variable may exist.**
Everything prefixed `VITE_` is compiled into the bundle and is public. The
current boilerplate gets this wrong today — `src/utils/crypto.utils.ts`
performs AES encryption with `VITE_AUTH_ENCRYPTION_KEY`, a key shipped to every
browser, which makes the encryption decorative. Removing `crypto-js` is
therefore a security fix, not a dependency cleanup. The bootstrap script and a
CI step both assert that no `VITE_*` key matches
`SECRET|KEY|TOKEN|PASSWORD|CREDENTIAL`.

### 11.4 Content Security Policy

The nginx image serving the built assets sets an explicit CSP, plus
`X-Content-Type-Options`, `Referrer-Policy` and `Permissions-Policy`. the reference dashboard's
Dockerfile does not, and a static-asset image is exactly where these belong.

The fleet's agent tooling is part of "everything done so far" and the generic

  entirely generic.
- `.claude/settings.json` (permissions and hooks skeleton), `CLAUDE.md` and

- `.claude/skills/README.md` explaining the skill pattern and pointing at the

## 14. Out of scope — and why

i18n, PWA/service worker and a third-party error tracker (Sentry) are **not**
included. None is present in the reference dashboard or the second reference dashboard, and none is a gap in
engineering practice — each is a product decision that a new project should
make deliberately. They ship as recipes in `docs/recipes/`, not as defaults.
OpenTelemetry web plus PostHog already cover error and performance telemetry.
