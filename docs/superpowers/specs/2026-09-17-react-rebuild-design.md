# React Boilerplate Rebuild — Design Spec

Status: approved in brainstorming
Session: https://claude.ai/code/session_018W6fi5MwVob2Vr1AexY5Mu
Date: 2026-09-17
Stream: 7 of 7 (see express-boilerplate's `2026-09-16-boilerplate-roadmap.md`)

## Problem

The current react-boilerplate uses an outdated stack: React 18, React Router,
Redux, Tailwind 3, React Hook Form, Zod 3. It does not align with the
express-boilerplate's shipped API routes, has no proper tests, no CI, and no
Dockerfile. Both production frontends (Ofluence/pulse, Consequential/pulse)
have already moved to React 19 + TanStack Router + Zustand + Tailwind 4.

## Solution

A full rewrite using the production-proven stack from Ofluence/pulse and
Consequential/pulse, with shadcn/ui as the component library.

## 3. Pages

### Auth Pages (unauthenticated — `_auth` layout)

All use the centered card layout (AuthLayout). Redirect to `/dashboard` if
already authenticated.

**Login** (`/login`):
- Email + password form (TanStack Form + Zod)
- "Forgot password?" link
- "Sign in with Google" button → redirects to `GET /api/v1/auth/google`
- On success: store access token in Zustand, redirect to dashboard
- Toast on error

**Register** (`/register`):
- Email, password, first name, last name form
- Password strength indicator
- On success: toast "Check your email for verification link", redirect to login
- "Already have an account?" link

**Forgot Password** (`/forgot-password`):
- Email-only form
- On success: toast "If that address has an account, a reset email has been sent"
- Same message regardless of whether email exists (Ruling G)

**Reset Password** (`/reset-password?token=...`):
- New password + confirm password form
- Token read from URL search params
- On success: toast "Password reset successfully", redirect to login

**Verify Email** (`/verify-email?token=...`):
- Token + password form (the boilerplate requires password at verification)
- Token read from URL search params
- On success: toast "Email verified", redirect to login

**OAuth Callback** (`/auth/callback`):
- No UI — reads the refresh cookie (set by backend), calls `POST /auth/refresh`
  to get access token, stores it, redirects to dashboard
- Shows spinner while processing
- On error: redirect to login with error toast

### App Pages (authenticated — `_app` layout)

All behind the AppLayout (sidebar + header + notification bell). Redirect to
`/login` if not authenticated.

**Dashboard** (`/dashboard`):
- Placeholder welcome page — derived projects fill this
- Shows user's name, tenant name if in a tenant context

**Profile** (`/profile`):
- View/edit first name, last name
- Shows email (read-only), auth providers list
- Change password form (if email provider exists)

**Notifications** (`/notifications`):
- Paginated list (TanStack Query with cursor pagination)
- Mark read / mark all read / delete
- Real-time updates via SSE (EventSource connected on mount)
- Notification preferences toggle

**Tenants** (`/tenants`):
- List user's tenants with role badges
- Create new tenant form (name, slug with live validation)

**Tenant Detail** (`/tenants/:slug`):
- Tenant info + settings
- Members list with role badges
- Add member (by email) — owner/admin only
- Change role / remove member — respects the actor→target matrix
- Settings: timezone, locale, metadata

## 4. Layouts

### AuthLayout

Centered card on a clean background. Logo at top. Responsive — full width
on mobile, max-w-md card on desktop. Dark mode support.

### AppLayout

- **Sidebar** (shadcn Sidebar component): tenant switcher at top, navigation
  links (Dashboard, Notifications, Tenants), user menu at bottom (Profile,
  Theme toggle, Logout)
- **Header**: breadcrumbs, notification bell with unread count badge
- **Content area**: scrollable, with max-width constraint
- Sidebar collapses to icons on narrow screens, toggleable

## 5. Auth & HTTP Layer

### Zustand Auth Store

```typescript
interface AuthState {
  accessToken: string | null
  user: User | null
  isAuthenticated: boolean
  isLoading: boolean
  login: (token: string, user: User) => void
  logout: () => void
  setToken: (token: string) => void
}
```

Access token stored in memory (Zustand — not localStorage). Refresh token
is an httpOnly cookie managed by the backend.

### Axios Interceptors

- **Request interceptor**: attaches `Authorization: Bearer <token>` from
  Zustand store
- **Response interceptor**: on 401 with `ACCESS_TOKEN_EXPIRED` code:
  1. Call `POST /api/v1/auth/refresh` (sends refresh cookie automatically)
  2. Store new access token
  3. Retry the original request
  4. If refresh fails: clear auth state, redirect to login

### SSE Connection

EventSource to `GET /api/v1/notifications/stream?token=<accessToken>`.
Connected on mount in AppLayout. Reconnects automatically (EventSource
built-in). Parses notification events and updates the notifications query
cache (TanStack Query `queryClient.setQueryData`).

## 6. UX Patterns

### User Feedback

- **Sonner toasts** for all actions: success (green), error (red), info (blue)
- **Loading states**: skeleton components on data-fetching pages, button
  spinners on form submissions, `isPending` from TanStack Query/Form
- **Optimistic updates** for mark-read, delete notification
- **Form validation**: inline errors below each field, red border on invalid,
  disabled submit button until valid

### Accessibility

All shadcn/ui components are Radix-based:
- Full ARIA attributes (roles, labels, descriptions)
- Keyboard navigation (Tab, Enter, Escape, Arrow keys)
- Focus management (trap focus in modals/dialogs, return focus on close)
- Screen reader announcements for toasts and alerts
- Color contrast meets WCAG AA (OKLCH tokens designed for it)

### Theming

- Light/dark/system mode via Zustand store + CSS class on `<html>`
- OKLCH color tokens from shadcn/ui (consistent across themes)
- Sidebar has its own color tokens (subtle background difference)
- Smooth transitions on theme switch

### Responsiveness

- Sidebar collapses at `md` breakpoint
- Auth forms: full width on mobile, centered card on desktop
- Tenant member table: horizontal scroll on mobile
- Touch-friendly button sizes (min 44px tap target)

## 7. Testing

- **Vitest** + **Testing Library** for component tests
- **MSW** (Mock Service Worker) for API mocking — no real HTTP calls in tests
- Test coverage: auth flow, form validation, protected route redirects,
  notification rendering, tenant CRUD interactions
- **CI workflow**: `.github/workflows/ci.yml` — lint + type-check + test + build

## 8. Dockerfile

Multi-stage build:
```dockerfile
# Stage 1: build
FROM node:24-alpine AS build
WORKDIR /app
COPY package.json pnpm-lock.yaml ./
RUN corepack enable && pnpm install --frozen-lockfile
COPY . .
RUN pnpm build

# Stage 2: serve
FROM nginx:alpine
COPY --from=build /app/dist /usr/share/nginx/html
COPY nginx.conf /etc/nginx/conf.d/default.conf
EXPOSE 80
```

`nginx.conf` handles SPA routing (`try_files $uri /index.html`).

## 10. What This Does NOT Include

- Server-side rendering (SPA only — matches production frontends)
- E2E tests (Playwright — follow-up)
- i18n / localization
- PWA / service worker
- Analytics / PostHog integration (project-specific)
- Admin panel (project-specific)
- File upload / media management
